# MiniCPM-V image and English workflow

ShipMBLang sends local still images and the user's English request to a configured
multimodal chat provider. ShipMBCompiler turns the returned proposal into English,
then parses and validates that English before it can generate bytecode. Images and
image-derived interpretations bypass persistent compiler memory.

The shared API/fixture contract is `shipmb-image-prose-v2`; the canonical example
is `examples/multimodal_contract_v2.json` in ShipMBCompiler. Add
`[[image:1]]`, `[[image:2]]`, and so on where each image belongs in the prose.
The language editor and compiler renumber image attachments in document order.
Compiler owns this contract and its compatibility cases. Language releases copy
the compiler modules into the 0.5.0 bundled snapshot and refresh its hash manifest.

## Local use

Configure `SHIPMB_MODEL_PROVIDER=openai_compatible`, `SHIPMB_MODEL_BASE_URL`, and
`SHIPMB_MODEL_NAME` for a local image-capable OpenAI-compatible server. Then pass
one or more local images in the same order as their anchors:

```powershell
$env:SHIPMB_MODEL_PROVIDER = "openai_compatible"
$env:SHIPMB_MODEL_BASE_URL = "http://127.0.0.1:8000/v1"
$env:SHIPMB_MODEL_NAME = "OpenBMB/MiniCPM-V-4.6"
python -m shipmblang compile "Read [[image:1]] and display the number." --pipeline direct --image .\number.png --memory off --format json
```

The compiler accepts at most four PNG, JPEG, GIF, WebP, or BMP images, with an
8 MiB per-file and 16 MiB total limit. Text-only compilation remains supported.
Images require an image-capable provider; they are not silently sent to a
text-only model.

## Training

`tools/train_minicpmv.py` launches MiniCPM-V 4.6 (1.3B parameters) QLoRA using
ms-swift and a batch size of one. It configures NF4 quantization, gradient
checkpointing, and DeepSpeed ZeRO-3 CPU offload, then records the dataset hash,
GPU, model, and training method in the output directory. An 8 GiB GPU is only a
target to preflight; the one-step `--pilot` measures actual fit and can fail due
to GPU or host-memory limits. It does not guarantee a full training run will fit.

Use Python 3.10–3.13 in an isolated training environment with CUDA PyTorch,
ms-swift's `minicpmv4_6` support, and the dependencies required by that SWIFT
release. Prepare a train-only JSONL file in SWIFT's custom conversation format:

```json
{"query":"Read the number shown in the image and display it.","response":"{\"paraphrase\":\"Display 7.\"}","images":["data/train/0001.png"],"split":"train"}
```

`images` may be empty for compiler prose examples. Keep benchmark evaluation
splits and meaning-level compiler holdouts out of this file. Before including
benchmark examples, verify dataset terms allow model training and local image
storage. For OCR/VQA tasks, retain provenance and the original licensed split;
do not redistribute source images through a model release without permission.

Run the preflight before the one-step memory pilot, then train only after reviewing
the dataset manifest and pilot result:

```powershell
python tools/train_minicpmv.py data/minicpmv-train.jsonl --preflight
python tools/train_minicpmv.py data/minicpmv-train.jsonl --output-dir output/minicpmv46-pilot --pilot
python tools/train_minicpmv.py data/minicpmv-train.jsonl --output-dir output/minicpmv46 --max-steps -1
```

Compare base and tuned checkpoints on the same frozen compiler-specific held-out
cases. Report translation fidelity, successful validated compilation, runtime
correctness, clarification/unsupported behavior, latency, artifact size, and
peak VRAM separately from upstream vision benchmark scores. The compiler repo's
`scripts/evaluate_multimodal.py` accepts a held-out JSONL manifest with
`case_id`, `source`, `split`, optional `intent_id`, `images`, `expected_status`,
and `expected_stdout`. It rejects training splits and duplicate intent IDs, and
reports compilation/runtime metrics, latency, and generated bytecode size. Run it
once per checkpoint against the same manifest, then compare the reports:

```powershell
# From the ShipMBCompiler repository; configure the base endpoint/model first.
python scripts/evaluate_multimodal.py data/compiler-holdout.jsonl --label base --checkpoint-path C:/models/MiniCPM-V-4.6 --output output/eval-base.json

# Point the same endpoint configuration at the tuned checkpoint, then rerun.
python scripts/evaluate_multimodal.py data/compiler-holdout.jsonl --label tuned --checkpoint-path output/minicpmv46 --output output/eval-tuned.json
```

The evaluator reports model/checkpoint size separately from generated bytecode
size. `--checkpoint-path` accepts a model or adapter file/directory; omit it if
the files are remote and record the upstream parameter count separately. Record
the base checkpoint as MiniCPM-V 4.6 (1.3B parameters) and record the tuned
adapter's on-disk size; do not imply the adapter is a new full model.

Keep DocVQA, MMBench, and OCRBench scores as separate upstream vision benchmark
reports using their official evaluators and held-out splits. The compiler JSONL
evaluator does not calculate those benchmark scores. Never train on official
evaluation splits.

Do not start a training run until the dataset's allowed use, train/evaluation
separation, CUDA environment, and actual memory pilot have been checked. As of
this release, no MiniCPM-V fine-tune has run and no DocVQA, MMBench, OCRBench, or
compiler-specific model scores are claimed. The language/compiler software test
counts are documented in the READMEs; they are not vision benchmark scores.
Video remains deferred until still-image code and weights are released.
